# Licence Check: Static Analysers

Author: Danial Boranbayev. Status: v1.0, 2026-11-28. Task: DIP-13. Reviewer: Andrey Rudov.

This document checks whether the three planned analysers (Bandit, Semgrep, CodeQL) can be used in the
service under their licence terms. It closes the open "licence check" item in
[technology-comparison.md](technology-comparison.md) (D6) and mitigates risk R2 in
[project-management.md](project-management.md).

This is an engineering reading of public licence texts, not legal advice. Sources were accessed on 2026-11-28.

## Scope: how we use the analysers

The answer depends on how the tool is used, so the use cases are fixed first.

| ID | Use case | Who runs it | Whose code is scanned |
|---|---|---|---|
| U1 | Diploma experiments: generate code with open-weight models and scan it to compare models | Our team | Code generated by us for research |
| U2 | Self-hosted service: a team deploys our Docker Compose stack on its own server | The deploying team | Code generated by that team's run |
| U3 | Hosted service: we run the service and let other people use it over the network | Us, for others | Code generated for other users |
| U4 | Snippet check (FR-14): a user uploads their own code, not generated by the service | Any of the above | User's own code, possibly closed source |

U1 is what the diploma needs. U2 is the deployment model preferred in the interviews
([evidence-of-relevance.md](evidence-of-relevance.md), interviews 2 and 3). U3 and U4 are possible future uses
and are checked so that the limits are known.
